# 스피또 스코프 계산·운영 기준

## 매일·매주 수집할 정보

공식 발행내역에서 회차별로 다음을 저장한다.

1. 상품, 회차, 판매 상태, 판매·지급기한
2. 발행매수와 판매점 입고율
3. 각 등위의 당첨수량, 지급수량, 미지급수량
4. 공식 기준일과 실제 수집시각
5. 고액 당첨 지급일, 판매점, 상품·회차·등위
6. 직전 관측 대비 입고율·미지급수량 변화
7. 스피또2000 1등 잔여의 짝수→홀수 전환과 새 단독 지급 판매점

최소 주 1회가 필요하지만, 1등은 지급일 기준으로 수시 반영될 수 있어 앱은 하루 4회 확인한다.

## 반드시 분리해서 해석할 지표

- `판매점 입고율`: 발행분 중 판매점에 누적 공급된 비율이다. 소비자 판매율이 아니다.
- `미지급수량`: 당첨수량에서 지급수량을 뺀 값이다. 미판매 당첨권 수가 아니다.
- `청구진행 프록시`: 5만원 이하 빈번 등위의 지급 진행률 중앙값으로 만든 미해결 모집단 추정치다. 판매 재고 추정이 아니다.
- `기본구조 기대값`: 발행 당시 전체 당첨구조로 계산한다. 공식 확률 비교용이다.
- `시나리오 기대값`: 미지급 당첨권이 사용자가 가정한 풀 `U` 안에 전부 있다고 놓은 민감도 분석이다.

## 세후 실수령 추정

- 200만원 이하: 비과세
- 200만원 초과: 구매비를 차감한 과세표준의 3억원 이하 구간 22%
- 3억원 초과분: 33%

실제 지급기관의 세무 처리가 우선한다.

## 전체 계산식

가격을 `c`, 가정한 미해결 전체매수를 `U`, 등위별 미지급수량을 `R_k`,
세전 당첨금을 `A_k`, 세후 실수령액을 `A_k^net`이라 한다.

```text
등위별 확률          p_k = R_k / U
1등만 기대값         EV_1 = p_1 × A_1
1~3등 기대값         EV_high = Σ(k=1..3) p_k × A_k
전체 기대값          EV_all = Σ p_k × A_k
세후 기대값          EV_net = Σ p_k × A_k^net
세후 ROI             ROI_net = EV_net / c
장당 기대손익        EV_net - c
```

손익분기 미해결 매수:

```text
U_break-even = Σ(R_k × A_k^net) / c
```

이 식은 `U < U_break-even`일 때만 해당 시나리오에서 세후 기대값이 양수임을 뜻한다.
공식 데이터가 실제 `U`를 제공하지 않으므로 앱의 슬라이더로 민감도를 확인한다.

청구진행 프록시:

```text
q = median(저액·빈번 등위의 지급수량 / 당첨수량)
U_proxy = 발행매수 × (1 - q)
```

여러 장 구매 시 한 번 이상 당첨될 확률:

```text
P(한 번 이상) = 1 - (1 - p)^n
```

한 번의 당첨만으로 전체 예산을 회수할 보수적 하한:

```text
p_cover = Σ p_k  (A_k^net >= n × c 인 등위)
P_cover = 1 - (1 - p_cover)^n
```

복수 소액당첨이 합쳐져 예산을 회수하는 경우는 제외하므로 실제 회수확률의 하한이지만,
각 `p_k` 자체가 시나리오 가정에 의존한다.

스피또2000 정확한 짝장을 보관받는 조건부 옵션:

```text
EV_option = EV + p_1 × q_pair × (A_1^net - c)
```

`q_pair`는 첫 장이 1등일 때 정확한 짝장이 미판매 상태이고 실제 구매 가능한 확률이다.

## 스케일별 기본 판단선

다음 값은 통계적 법칙이 아니라 표시를 위한 보수적 기본값이며 앱에서 변경할 수 있다.

| 구간 | 기준 | 해석 |
|---|---:|---|
| 기대손실 | 세후 ROI < 100% | 평균적으로 구매비보다 적게 회수 |
| 모형상 양수 | 100~125% | 오차 완충이 없고 희귀 고액권 의존 가능 |
| 완충 기대값 | 125~150% | 25% 이상 오차 완충, 여전히 프록시 |
| 강한 관찰 신호 | ROI ≥150% + 10만원 단일회수 하한 ≥20% | 낮은 횟수의 실현 가능성도 함께 관찰 |

EV가 양수여도 1등 한 장이 대부분의 기대값을 만들면 낮은 시도횟수에서 손실 확률은 매우 높다.
따라서 앱은 다음 예산별로 기대손익과 `P_cover`를 함께 표시한다.

- 1장
- 1만원
- 5만원
- 10만원
- 50만원
- 100만원
- 사용자 지정 예산

## 전략 등급

### 확정·유효

1. 미지급 1등 0매 회차를 1등 목표에서 제외한다.
2. 스피또2000은 목표가 최고당첨금이면 완전한 세트를 산다.
3. 1등 발생확률이 목표라면 서로 다른 완전 세트의 낱장을 비교한다.
4. 당첨금 재구매와 손실 추격을 하지 않는다.

### 조건부 유효

1. 온전한 스피또2000 세트 한 장을 긁는 동안 정확한 짝장을 보관받고, 1등일 때만 짝장을 산다.
2. 짝수→홀수 전환 직후 새 단독 지급 판매점을 확인한다. 단, 지급일은 판매일이 아니며 짝장이 이미 판매됐을 수 있다.

### 검증 불가 또는 무효

1. 명당·특정 지역 순회
2. 입고율만으로 현재 확률 계산
3. 미지급수량을 미판매수량으로 간주
4. 지급일의 요일·계절 패턴으로 구매시점 선택
5. 일련번호·북번호·정확한 짝장 외 인접 티켓 추적

## 자동화와 알림

- GitHub Actions가 UTC 00:17, 06:17, 12:17, 18:17에 공식 데이터를 확인한다.
- 상태가 바뀌면 `data/speetto/history.jsonl`에 스냅숏을 추가한다.
- 모든 확인 결과는 `data/speetto/checks.jsonl`에 최대 2,000행 보관한다.
- 대시보드는 앱을 연 상태에서 15분마다 최신 JSON을 다시 확인한다.
- 브라우저 알림은 앱을 열거나 다시 방문했을 때 새 상태를 감지한다.
- 앱이 닫힌 상태의 서버 푸시는 제공하지 않는다. 대신 `alerts.xml` 구독 또는 저장소
  Secret `SPEETTO_ALERT_WEBHOOK_URL`을 통한 웹훅을 사용할 수 있다.
